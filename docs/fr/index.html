A Fluent Logging API for PHP

Des logs qui expriment votre intention.

Choisissez un niveau, ajoutez du contexte structuré et décidez quand écrire. Phlogger adapte l'approche fluide de Google Flogger à PHP moderne et au logger PSR-3 que vous utilisez déjà.

PHP 8.5+Seule dépendance d'exécution : psr/logBuilders immuables
use Phlogger\FluentLogger;
use Phlogger\Level;

$logger = new FluentLogger($psrBackend, minimumLevel: Level::Info);

$logger->atWarning()
    ->withCause($exception)
    ->atMostEvery(30)
    ->log('Payment failed for order {id}', ['id' => $orderId]);

Installation

Phlogger nécessite PHP 8.5 ou une version ultérieure. Sa seule dépendance d'exécution est psr/log. Fournissez un backend PSR-3 : le logger de votre application, un logger de test ou Psr\Log\NullLogger.

Installez la version publiée directement depuis GitHub grâce à la prise en charge des dépôts VCS par Composer :

composer config repositories.phlogger vcs https://github.com/roukmoute/phlogger
composer require "roukmoute/phlogger:^0.1"

Phlogger fournit l'API de logging. Le backend fourni assure le stockage, la mise en forme et le transport.

Premiers pas

Chaque méthode at*() démarre un enregistrement fluide. Terminez par log() pour l'émettre. Les huit niveaux PSR-3 sont disponibles : debug, info, notice, warning, error, critical, alert et emergency.

$logger->atInfo()
    ->with('user_id', $userId)
    ->log('User {user_id} signed in');

$logger->at(Level::Notice)
    ->withContext(['job' => 'daily-report', 'rows' => 120])
    ->log('Report generated');

$logger->atError()
    ->withCause($exception)
    ->log('Report generation failed');

log() transmet le modèle du message et son contexte au backend. L'interpolation des paramètres appartient au backend. Utilisez logf() pour demander explicitement une mise en forme avec sprintf().

$logger->atInfo()->logf('Processed %d rows in %.2f seconds', $rows, $seconds);

Contexte et exceptions

Utilisez with() pour une valeur et withContext() pour un groupe. Le contexte du logger, celui de l'enregistrement fluide puis celui de l'appel terminal sont fusionnés dans cet ordre : la valeur la plus spécifique l'emporte.

$requestLogger = $logger->withContext([
    'request_id' => $requestId,
    'component' => 'http',
]);

$requestLogger->atInfo()
    ->with('component', 'checkout')
    ->log('Checkout started', ['component' => 'payment']);
// The backend receives component=payment and request_id=$requestId.

Le logger et les builders fluides sont immuables. Ajouter du contexte retourne une nouvelle valeur : le logger d'origine conserve ses valeurs par défaut. Les clones contextuels partagent le même état de limitation.

withCause($throwable) place la cause sous la clé PSR-3 exception. Les exceptions et les erreurs PHP sont acceptées. withCause(null) attribue null à cette clé et efface ainsi une cause précédente. Le contexte de l'appel terminal log() peut remplacer cette clé.

Les tableaux, objets, valeurs nulles et closures ordinaires restent des données structurées. Phlogger ne convertit pas les valeurs arbitraires en chaînes et n'exécute pas les closures ordinaires du contexte.

Évaluation différée

Encapsulez une valeur de contexte ou un argument de mise en forme coûteux dans LazyValue::of(). Le message peut également être une closure. Ces calculs sont exécutés seulement après l'admission de l'enregistrement par les filtres, conditions et limitations de Phlogger.

use Phlogger\LazyValue;

$logger->atDebug()
    ->with('summary', LazyValue::of(fn () => calculateSummary()))
    ->log('Summary: {summary}');

$logger->atDebug()
    ->log(fn () => buildDiagnosticMessage());

$logger->atInfo()
    ->every(100)
    ->logf('Queue size: %d', LazyValue::of(fn () => countQueue()));

Une même valeur différée est évaluée une fois par enregistrement, puis son résultat est transmis au backend. Seules les valeurs au premier niveau du contexte sont résolues : Phlogger ne parcourt pas les tableaux ou objets imbriqués. Une closure ordinaire du contexte est conservée telle quelle.

Le backend peut encore filtrer l'enregistrement. PSR-3 ne permet pas de consulter les niveaux actifs d'un backend. Configurez minimumLevel ou filter dans Phlogger pour éviter les calculs différés aux niveaux désactivés par votre application.

Évitez les effets de bord applicatifs dans les callbacks différés. Les exceptions levées par les callbacks et par le backend remontent à l'appelant.

Filtres et conditions

Le niveau minimum par défaut est Level::Debug. Augmentez-le pour exclure les enregistrements plus détaillés. Une closure filter optionnelle reçoit le Level sélectionné et retourne un booléen ; elle restreint davantage le logging.

$logger = new FluentLogger(
    $psrBackend,
    minimumLevel: Level::Info,
    filter: fn (Level $level): bool => $level !== Level::Notice,
);

$logger->atWarning()
    ->when(fn () => $queue->isOverloaded())
    ->log('Queue is overloaded');

$logger->atInfo()
    ->when($shouldAudit)
    ->log('Audit event recorded');

Plusieurs conditions when() doivent toutes autoriser l'enregistrement. isEnabled() permet de vérifier le niveau avant un calcul séparé : cette méthode ne consomme aucun quota et ne prédit pas le résultat des conditions ou limitations.

if ($logger->atDebug()->isEnabled()) {
    // Prefer LazyValue for work belonging to a single record.
}

Limitation des logs

Contrôlez les logs répétitifs directement au site d'appel. Les limites sont vérifiées avant l'évaluation différée du message et du contexte.

MéthodeComportement
every(3)Admet le premier appel, puis les appels 4, 7, 10, etc. every(1) n'a aucun effet.
first(5)Admet seulement les cinq premiers enregistrements éligibles pour ce site et cette politique. first(0) supprime tous les enregistrements.
atMostEvery(30)Admet le premier appel, puis impose au moins 30 secondes depuis le dernier appel admis. Zéro désactive cette limite temporelle.
 
$logger->atWarning()
    ->atMostEvery(30)
    ->log('Remote service is unavailable');

$logger->atDebug()
    ->first(5)
    ->log('Initial sample', ['sample' => $sample]);

Si une chaîne combine plusieurs limites, toutes doivent autoriser l'appel. Les compteurs d'intervalle et la fenêtre temporelle sont réinitialisés ensemble après admission. Un enregistrement rejeté par un filtre de niveau ou une condition ne consomme aucun quota.

every() exige un nombre strictement positif ; first() accepte zéro ou un nombre positif. atMostEvery() exige une durée finie et non négative en secondes. Répéter une méthode de limitation remplace la valeur précédente de cette méthode.

Sites d'appel et clés explicites

Par défaut, l'état dépend du fichier et de la ligne de l'appel terminal, du niveau et de la politique de limitation, au sein de la famille du logger. Des lignes différentes sont indépendantes. Deux appels sur la même ligne avec le même niveau et la même politique partagent leur état.

Utilisez withRateLimitKey() pour choisir une clé stable, notamment dans une fonction qui encapsule le logging. Une clé partage son état seulement si le niveau et la politique sont également identiques.

$logger->atWarning()
    ->withRateLimitKey('payment-provider-unavailable')
    ->atMostEvery(30)
    ->log('Payment provider unavailable');

Durée de vie et mémoire

L'état est local à la famille du logger et au processus PHP courant. Les clones contextuels le partagent ; des loggers construits séparément et des workers distincts ne le partagent pas. Les limites ne coordonnent pas plusieurs workers PHP-FPM ou instances d'application.

Le stockage contient jusqu'à 1 024 entrées par défaut. Le paramètre de constructeur rateLimitCapacity permet de modifier cette capacité. Quand il est plein, l'entrée utilisée le moins récemment est supprimée. Une clé supprimée recommence avec un quota neuf. Préférez des clés stables à des identifiants issus d'un ensemble illimité.

Les limites temporelles utilisent une horloge monotone. Une closure clock optionnelle dans le constructeur, retournant des secondes, permet des tests déterministes. resetRateLimits() vide le stockage partagé.

L'admission consomme le quota. Un enregistrement admis par Phlogger consomme sa limite même si un callback différé lève une exception, si le backend échoue ou s'il refuse l'écriture. PSR-3 ne permet pas à Phlogger de confirmer la livraison.

Intégration PSR-3

FluentLogger implémente Psr\Log\LoggerInterface. Fournissez-le aux bibliothèques qui attendent un logger PSR-3 ou utilisez ses méthodes classiques à côté des appels fluides.

use Psr\Log\LoggerInterface;

function reportFailure(LoggerInterface $logger, Throwable $error): void
{
    $logger->error('Operation failed', ['exception' => $error]);
}

reportFailure($logger, $exception);
$logger->info('User {id} signed in', ['id' => $userId]);
$logger->log('notice', 'Job completed', ['job' => $jobId]);

Les méthodes PSR-3 directes utilisent les mêmes filtres de niveau et le contexte par défaut. Le log() terminal d'une chaîne fluide reçoit un message ; le log() PSR-3 du logger reçoit un niveau puis un message. Les niveaux inconnus provoquent une Psr\Log\InvalidArgumentException.

Pour préserver la compatibilité PSR-3, les méthodes directes du logger conservent toutes les valeurs de contexte telles qu'elles sont fournies, y compris les objets LazyValue. La résolution des valeurs différées est une fonctionnalité des enregistrements fluides.

at(Level|string), huit méthodes at*()Démarrer un enregistrement fluide immuable à un niveau PSR-3.
with(string, mixed)Ajouter une valeur de contexte.
withContext(array)Fusionner le contexte d'un enregistrement ou créer un logger contextuel.
withCause(?Throwable)Définir la valeur de contexte exception, y compris null.
when(bool|Closure)Exiger une condition avant d'admettre un enregistrement.
every(int), first(int), atMostEvery(float)Limiter les appels par fréquence, nombre ou durée en secondes.
withRateLimitKey(string)Choisir la clé de l'état de limitation à la place du site d'appel.
isEnabled()Vérifier le niveau sans consommer de quota.
log(string|Stringable|Closure, array)Émettre un modèle de message et du contexte structuré. Une closure de message retourne une chaîne ou un Stringable.
